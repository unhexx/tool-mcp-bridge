## Design Document Review: function-over-sdk-stdio

### Summary

Approve. Open issues: 0. The revised draft is still one named proposal, function-over-sdk-stdio, with status Draft, and the nine round-1 items are present in the design text and match the current tree.

### Strengths

- Round 1 is implemented in the draft, not only in the writer's response, and is not reopened. The finished call requires `resultType: "complete"` along with `content`, `structuredContent`, and `isError`. The `input_required` object sets both `inputRequests.confirm` (`elicitation/create`, message `confirm ping`) and `requestState: "ping-state"`. `run()` and `execute()` return that inner dump; `tool_http` nests it under `result`.
- The legacy fixture is a line transcript: `server/discover` gets a JSON-RPC error object `{"code": -32601, "message": "Method not found"}` with the request's `id`, `notifications/initialized` gets no stdout line, and `tools/list` / `tools/call` name tool `ping` and text `pong` with `resultType: "complete"`. The only supported POST body is `{"arguments": {server_label, tool_name, arguments, list_only}}`. A raw object that itself contains `arguments` is called out as a misread list, not a second shape.
- Success list and invoke bodies omit `command`, `env`, and `stderr`. The High threat and the Risks table still record that HTTP 400 `error` and `trace` can carry argv from SDK or OS exceptions. That residual is not described as closed. `server command required` is attributed to today's invoke check in `run()`; the non-empty-string element rule is stated as new.
- Decision 4 and the Timeout section agree: `MCP_TIMEOUT` cancels the session, shielded SDK shutdown may overrun, and `_bounded` is the one mapping of a direct `TimeoutError`, a direct `MCPError` whose code is `REQUEST_TIMEOUT` (`-32001`), and a single-leaf group of either one onto `mcp timeout after {n}s: {label}`. `run()` only unwraps a group that still escaped. The env property is locked by a real stdio `env_probe`, with `env` omitted and with `env` set, and `TOOL_TOKEN` and `MCP_SERVERS` absent both times.
- PR 2 includes the `tool_mcp_bridge` logger, `stdio_client(..., errlog=buffer)`, required `client_info`, and the raise-contract tests. PR 3 binds `make_handler` on `127.0.0.1` and asserts HTTP 200 for a nested `isError: true` result and HTTP 400 whose `error` starts with `mcp timeout after 1s`. `tool_http.py` stays unchanged. The ADR text stays in this draft; `docs/adr/0001-mcp-sdk-stdio-client.md` is created by the first implementation PR, not by this pass.
- Background claims match the code: private `{"tool", "arguments"}` envelope, list returns `command` without spawning, stdio-only invoke, inherited environment, `MCP_TIMEOUT` default 20, empty runtime dependencies, `requires-python >=3.11`, CI on 3.12, default bind `127.0.0.1:8090`, bearer gate and 2_000_000 byte cap, HTTP 401 for `PermissionError` and HTTP 400 with a 1500-character trace otherwise, health and schema unauthenticated, Docker uid 10001, and the Compose limits including tmpfs `/tmp` at 64m. There is no ADR directory under `docs/`, `.agent/`, or `agentic_loop_template`. The README curl is `{"arguments":{}}`.
- Silence and `-32022` stay a recorded risk, with S2 as the alternative. That gap is not reopened. SDK names that are not in `docs/design/research/` either have a PR 2 confirm-and-fallback (`tool.input_schema`, `exc.code` versus `exc.error.code`, the `Implementation` module, the `ElicitRequest` constructor, dropping legacy `resultType` only) or match the SDK pages this draft already cites (`session.call_tool(..., allow_input_required=True)`, `stdio_client(..., errlog=)`, `read_timeout_seconds`, `list_tools(cursor=)` / `next_cursor`, `mcp.run()` defaulting to stdio, and the `ToolError` text pattern). The low-level `input_required` fixture's plaintext `ping-state` is consistent with that server not sealing `request_state` unless the seal is opted in; the seal sentence applies to `MCPServer` children.
